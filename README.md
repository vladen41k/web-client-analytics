# web-client-analytics

Небольшой веб-клиент для просмотра событий из analytics-сервиса. Приложение поднимает Go HTTP-сервер, раздаёт статический интерфейс, проксирует `GET /v1/events` в backend и подключается к `WebSocket /v1/ws`, чтобы показывать новые события в реальном времени.

## Возможности

- загрузка текущей истории событий по HTTP;
- автоматическое подключение к websocket с переподключением;
- отображение новых событий во всплывающих уведомлениях;
- проксирование analytics backend за одним клиентским адресом.

## Требования

- Go `1.25.5` или совместимая версия;
- доступный analytics backend с HTTP endpoint `GET /v1/events`;
- websocket endpoint `GET /v1/ws` на стороне analytics backend.

## Быстрый старт

1. Скопируйте пример конфигурации:

```bash
cp .env.example .env
```

2. При необходимости измените значения в `.env`.

3. Запустите приложение:

```bash
make run
```

4. Откройте в браузере `http://localhost:8080`.

## Переменные окружения

Приложение читает `.env`, если файл существует.

| Переменная | Значение по умолчанию | Описание |
| --- | --- | --- |
| `CLIENT_ADDR` | `:8080` | адрес, на котором запускается веб-клиент |
| `ANALYTICS_HTTP_URL` | `http://localhost:8082` | базовый HTTP URL analytics backend |
| `ANALYTICS_WS_URL` | вычисляется автоматически | полный websocket URL для событий; если не задан, строится из `ANALYTICS_HTTP_URL` |

Пример:

```env
CLIENT_ADDR=:8080
ANALYTICS_HTTP_URL=http://localhost:8082
ANALYTICS_WS_URL=ws://localhost:8082/v1/ws
```

## Как это работает

- `GET /` рендерит HTML-страницу и передаёт в неё клиентскую конфигурацию;
- `GET /styles.css` и `GET /app.js` раздаются как статические файлы;
- `GET /v1/events` проксируется в analytics backend;
- `GET /v1/ws` проксируется в analytics backend для websocket-подключения;
- `GET /config.json` возвращает клиентскую конфигурацию в JSON.

В браузере UI:

- загружает список событий через `fetch`;
- показывает статус HTTP и websocket-подключения;
- принимает новые события через websocket;
- добавляет новые события в начало списка и показывает toast-уведомление.

## Структура проекта

## Проверка

После запуска должны работать два сценария:

1. страница открывается по адресу `http://localhost:8080` и показывает историю событий;
2. при поступлении нового события через websocket оно появляется вверху списка и во всплывающем уведомлении.
